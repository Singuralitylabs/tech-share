## Claude Code とは ―「作業をする」AI

ひとことで言うと、**ターミナルの中で動く、AIの開発パートナー**。AIに"聞く"のではなく、**AIと"作る"ための道具**です。

| これまでのチャットAI | Claude Code |
|---|---|
| 人が状況を説明する | **AIが自分でファイルを読みに行く** |
| コードをもらう | **AIが自分で書き換える** |
| **人がコピペして戻す** | 人は指示と確認だけ |

- 「質問に答えるAI」ではなく、**「作業をするAI」**。ここが決定的な違い
- ただし勝手に進みません。**ファイルを変更する前に必ず許可を聞いてきます**

## なぜ今、これが来ているのか

- **長い作業をやり切れるようになった**
  - 昨年までは「書いている途中を補完する」が中心
  - 今は「このタスクを丸ごとお願い」が成立する
- **コピペの往復が消えた**
  - AIが自分でプロジェクトを読みに行ける
  - 毎回、人が状況を説明しなくてよくなった
- **"任せる"と"暴走しない"が両立した**
  - 変更前の許可確認、作る前の計画（PART 06）
  - だから安心して任せられる

## AI駆動開発は、この4つを回すだけ

1. **指示する**
   やりたいことを言葉で伝える
2. **AIが作る**
   ファイルを作る・直す
3. **確認する**
   **自分の目で結果を見る**
4. **改善する**
   直したい点だけを伝える

一番よくある失敗は、**③をサボること**。「できました」を鵜呑みにすると、ズレが積み上がります。

## 指示のコツは、3つだけ

- **やりたいことを書く**
  - 「どう作るか」ではなく「何が欲しいか」
  - 作り方はAIが考える
- **完成の条件を書く**
  - 「ブラウザで開いて一覧が見えたらOK」
  - 判断できる形にする
- **ダメだった点だけ伝える**
  - 毎回ゼロから説明し直さない
  - 良かった所は触らなくていい

<!-- _header: 'PART 05 · バイブコーディングの壁' -->

## 雰囲気で作れる。でも、大きくなると崩れる

いま体験した進め方＝**バイブコーディング**（雰囲気で指示して、雰囲気で直す）。**小さいものには今でも最速**です。

ただし規模が大きくなると、こうなります。

- **前に決めたことを忘れる** ― AIは毎回の指示を見て動くので、全体の方針が共有されていない
- **直したはずの場所が元に戻る** ― 「直して」の繰り返しで打ち消し合う
- **人間の側も、どこまで進んだか分からなくなる**

原因はAIではなく、**「何を作るか」が決まらないまま作り始めていること**。人間同士でも同じです。

| いきなり作る | 計画してから作る |
|---|---|

| 何が変わったか分からない | **事前に読んで判断できる** |

- 使い分けが答えです。**小さければそのまま、大きければ計画を挟む**

## 作らせる前に、計画を出させる

Claude Code には、**作る前に作業計画を出させて、人間が読んでからOKを出す**進め方があります（**プランモード**）。

**使い方はキー操作ひとつ**

> **`Shift` + `Tab` を 2回押す**（打ち込むのではなく、キーを押します）

- `Shift + Tab` は「通常 → 編集を自動承認 → **プランモード**」と切り替わります
- プランモードの間、Claude Code は **調べるだけで、ファイルを書き換えません**
- 代わりに「こう進めます」という **計画** を出してきます

## 計画を読むときの、3つの観点

- **何をするつもりか、自分の言葉で言えるか**

- **想定より大きくないか**

- **やってほしくないことが混じっていないか**
  - 混じっていたら、そこだけ伝える

## `/init` ― 同じ説明を、二度しなくてよくなる

ハンズオン中、**毎回同じ前提を説明し直している**感覚はありませんでしたか。それを解決するのが `/init` です。

```
/init
```

- Claude Code が **プロジェクトの中身を自分で調べて、`CLAUDE.md` というメモを作ります**
- この `CLAUDE.md` は **次回以降、毎回自動で読み込まれます**
- つまり「このプロジェクトはこういうものです」を **一度書けば済む**

**いま作業フォルダで打ってみてください**（1分）。できた `CLAUDE.md` を開いて眺めてみましょう。

<!-- _header: 'PART 08 · 基本コマンド' -->

## `CLAUDE.md` とは ― AIへの申し送りノート

`/init` が作るのは、**ただのテキストファイル**（Markdown）。作業フォルダの直下に置かれ、**起動のたびに自動で読み込まれます**。

```
# CLAUDE.md

## このプロジェクトについて
ふりかえりを書き留める1枚のHTMLページ。
index.html の1ファイルだけで動く。ビルドは不要。

## お願い
- 返答は日本語で
- ファイルを増やさず index.html の中で完結させる
```

- 特別な書き方はありません。**読めば分かる文章**で大丈夫です

## `CLAUDE.md` は、手で書き足していい

`/init` が作るのは **たたき台** です。運用の本番は、ここにチームのルールを足していくこと。

- 「**日本語で返答して**」
- 「**このフォルダは触らないで**」
- 「**コミットの前に必ず確認して**」
- 「**この書き方に合わせて**」

- 書き足すほど、**説明しなくても意図どおりに動くようになります**
- 開発では、これを **チームで共有**（リポジトリに置く）のが定番の使い方です

## 覚えるのは、この4つでいい

- **最初に打つ ― `/init`**
  - プロジェクトに記憶を持たせる
- **流れを切る ― `/clear`**
  - 別の作業に移るときは、続けるよりリセットした方が結果が良い
- **止める ― Esc キー**
  - 違う方向に走り出したら即座に押す。最重要キー
- **戻す ― `/rewind`**
  - 前の状態まで巻き戻す。手戻りが怖くなくなる

## あと3つだけ、知っておくと便利

- **`@` でファイルを指せる**　例：`@index.html を直して` ― そのファイルを見てもらえます
- **`/model`**　使うモデルを切り替える
- **`/help`**　使えるコマンドの一覧が出る

> **`/help` だけ覚えておけば、残りは自分で探せます**

- 今日は触れませんでしたが、この先には **サブエージェント・MCP・自動化** といった仕組みもあります

**はじめる前に**

- インストールとログインは社内ポータルの案内に従ってください

## OS別コマンド対応表（持ち帰り用）

| やりたいこと | Mac（ターミナル） | Windows（PowerShell） | マウスでのやり方 |
|---|---|---|---|
| フォルダを作る | `mkdir ~/Desktop/techshare-demo` | `mkdir ~\Desktop\techshare-demo` | 右クリック →「新規フォルダ」 |
| そのフォルダでターミナルを開く | `cd ~/Desktop/techshare-demo` | `cd ~\Desktop\techshare-demo` | Mac：`cd ` の後にドラッグ&ドロップ<br>Windows：アドレスバーに `powershell` |
| Claude Code を起動する | `claude` | `claude` | （ここだけはターミナル） |
| 作ったページを開く | `open index.html` | `start index.html` | **`index.html` をダブルクリック** |
| 今いる場所を確認する | `pwd` | `pwd` | フォルダのアドレスバーを見る |

- **`mkdir -p` は使わない** ― `cmd.exe` では `-p` という名前のフォルダができてしまいます
- Windowsで `cd` が失敗したら、デスクトップが **OneDrive配下** の環境です。マウス操作に切り替えてください
