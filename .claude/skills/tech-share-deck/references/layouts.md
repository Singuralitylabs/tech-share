# レイアウトクラス早見表（`themes/singularity.css`）

各スライドは `<!-- _class: ... -->` でレイアウトを選ぶ。クラスは1行に半角スペース区切りでまとめる（2行書くと後勝ちで先の行が消える）。
CSS は Markdown の**構造**（`ul` / `ol` / `table` / `h1`）に対して装飾を当てるので、下の書き方の形を崩すと見た目も崩れる。

目次：共通の骨格 / lead / 本文（クラスなし） / stat / trend / flow / grid / ba / center / dense / pair / refs・split / src / **体験会デッキ：lead tkt・tkb** / 選び方

---

## 共通の骨格（本文スライド）

```markdown
<!-- _class: grid -->
<!-- _header: 'PART 02 · 申し送りノートとは' -->

## ひとことスライド文言案をそのまま見出しに

- 要点（3〜4項目）

<!--
発表者ノート。企画 Issue の「話すポイント」「見せる数字/エピソード」「補足メモ」をここへ。
所要時間（例：2分）や、口頭で添える補足、聞かれたら答える内容もここ。
-->
```

- `_header` は `'OVERVIEW'`（冒頭のゴール・流れ）、`'PART 0X · パート名'`（本編）、`'PART 0X · ハンズオン① / STEP 1'`（手順）、`'CLOSING'` または最後の PART（まとめ）、`'APPENDIX · 出典 (1/2)'`（付録）。パート名は企画 Issue のタイムテーブルから短く取る。
- 付録（APPENDIX）スライドは `<!-- _footer: '' -->` でフッターを消す。

---

## lead（表紙）

```markdown
<!-- _class: lead -->
<!-- _paginate: false -->
<!-- _footer: '' -->

<p class="kicker">2026.10.05 ｜ ハンズオン（約60分）</p>

# タイトル<br>サブタイトル

<p class="org">シンギュラリティ・ラボ</p>

<!--
企画 Issue：https://github.com/Singuralitylabs/tech-share/issues/N
狙い：（Issue の狙い）
通しのメッセージ：（Issue の通しのメッセージ）
対象：…／前提：…
-->
```

- kicker は `YYYY.MM.DD`、形式があれば ` ｜ ハンズオン（約60分）` のように添える（LT・座学で時間を書かない既存例もある）。
- サブタイトルを独立させたいときは `# タイトル` の下に `> サブタイトル` でもよい（引用は表紙用に白抜きで描画される）。
- コメントの**1行目**が `企画 Issue：URL`。これがデッキ → 企画の唯一の導線。

## 本文（クラスなし）

一番よく使う。見出し＋箇条書き3〜4項目＋必要なら最後に引用で「持ち帰りの一文」。

```markdown
## 今日のゴールと、進め方

- ゴールは **自分専用の CLAUDE.md を書き、AIの振る舞いが変わるのを見る** こと
- 「説明 → 手を動かす」を、何度か繰り返します

> **手が止まったら、すぐチャットへ。進行より復帰を優先します**
```

---

## stat（大きな数字1つ）

企画の「見せる数字/エピソード（1つ）」がそのまま1つの数字になるときに使う。`#`（h1）が 128px の数字になる。

```markdown
<!-- _class: stat -->

## だから今日のメインは、GitHub Pages

# 0円

- 補足1
- 補足2
```

---

## trend（推移レール）

左から右へ値が移る様子（シェア推移など）。`ul` の各 `li` の `**太字**` が大きな数字、最後の項目が強調される。3〜4項目。

```markdown
<!-- _class: trend -->

## 1強から、多極化へ

- **65%**
  2024年12月
- **53%**
  2025年12月
- **46%**
  2026年5月
```

---

## flow（連番ステップ）

`ol` が横並びのカードになり、番号と ▶ が自動で付く。`**太字**`＝ステップ名、`*斜体*`＝時期や種別の小ラベル、残りが説明。3〜5ステップ。

```markdown
<!-- _class: flow -->

## 今日の流れ

1. **まず1周まわす**
   *ハンズオン①*
   指示して、作らせて、自分の目で見る
2. **壁にぶつかる**
   *座学*
   大きくなると崩れる理由を知る
```

---

## grid（2×2 カード）

トップレベル `ul` の各項目がカード。4項目で 2×2、3項目なら横1列に3枚。子リストが小さな説明文になる。5項目以上は入らない。

```markdown
<!-- _class: grid -->

## 今回の着眼点

- **コスト**
  - 性能より、価格と用途で選ぶ
- **使い方**
  - 道具から自律する相棒へ
- **安全・規制**
  - 能力が対策を追い越した
```

---

## ba（ビフォー/アフター）

企画の「各パートの型」がビフォー/アフターのときの主力。2列の表で、左がグレー（以前）・右が濃紺罫線（今）。表の下に箇条書き2〜3個を添えられる。

```markdown
<!-- _class: ba -->

## "どれが賢いか"だけでは、もう選べない

| 半年前 | 今 |
|---|---|
| 「どれが賢いか」で選ぶ | 「用途とコスト」で選ぶ |

- 補足
```

---

## center（中央寄せ・引用で一言）

パートの核心や、たとえ話を1枚で言い切るとき。引用（`>`）を主役にする。

```markdown
<!-- _class: center -->

## 道具 → 自分で回り続ける相棒

> 同じモデルでも、**"職場"が違えば別人**になる。

- 補足（2〜4項目まで）
```

---

## dense（手順スライド）

ハンズオンで「出しっぱなし」にする手順。`pre` と引用が詰まり、行数を稼げる。表で Windows / Mac を並べるのも定番。

- `pre`（コードブロック）は**参加者がそのまま打ち込むコマンドや指示文**だけ。テーマ上ターミナル風に描画されるので、キー操作（`Shift + Tab` など）を入れると打ち込むものと誤解される。キー操作は `> **`Shift + Tab` を2回押して、計画モードにする**` のように引用＋インラインコードで書く。

~~~markdown
<!-- _class: dense -->
<!-- _header: 'PART 04 · ハンズオン① / STEP 1' -->

## STEP 1｜フォルダを作って、そこでターミナルを開く

| | Windows | Mac |
|---|---|---|
| ① フォルダを作る | … | … |

```
mkdir ~/Desktop/techshare-demo
```
~~~

## pair / pair wide（本文＋右の図・QR）

右側に画像を置く。raw HTML の `<p class="fig">` が必須。広い図（スクリーンショット）は `pair wide`。

```markdown
<!-- _class: pair -->

## 見出し

- 本文

<p class="fig">
<img src="../assets/xxx.png" alt="説明" width="200">
キャプション
</p>
```

## refs・split（参考・注記）

- `refs`：18px の小さめ本文。参考・注記・補足。
- `split`：右40%が青グラデのパネルになり、**本文幅が半分**になる。単独でも使えるが、主に `<!-- _class: refs split -->` で最後の注記スライドに使う。項目が多いとはみ出す（5項目程度まで）。

```markdown
<!-- _class: refs split -->
<!-- _header: 'APPENDIX · 注記' -->
<!-- _footer: '' -->

## 注記

- **市場シェア**：測定手法で数値が変わる
- **時点**：2026年7月時点の整理
```

## src（出典リスト）

15px の密なリスト。項目は「**主張（数値）**（出典元）」＋改行して「媒体名 <URL>」。多ければ `(1/2)` `(2/2)` に分ける。**`refs` と併用しない**（font-size が衝突して 18px になる）。

```markdown
<!-- _class: src -->
<!-- _header: 'APPENDIX · 出典 (1/2)' -->
<!-- _footer: '' -->

## 出典 ─ シェアと価格

- **ChatGPTシェア 46.4%（26/5）**（Sensor Tower・アプリ利用ベース）
  TechCrunch <https://techcrunch.com/...>
```

## 体験会デッキ（`体験会` ラベル）：lead tkt・tkb

体験会デッキは、前後の定型スライド（`tk`）と見た目をそろえるため、**表紙は `lead tkt`、本編の全スライドは `tkb`** を使う（`tk` は定型スライド専用で、本編には付けない）。適用例：`decks/20261102_skills.md`。

### lead tkt（体験会の表紙）

前回の体験会資料の表紙と同じ中央寄せ。**日付の kicker は付けない**。

```markdown
<!-- _class: lead tkt -->
<!-- _paginate: false -->
<!-- _footer: '' -->

# 〇〇 体験会

<p class="sub">その回のテーマ</p>

<p class="org">シンギュラリティ・ラボ</p>

<!--
企画 Issue：https://github.com/Singuralitylabs/tech-share/issues/N
狙い：…
-->
```

- 見出しは `# <体験会名> 体験会` で固定（例：`# AI駆動開発 体験会`、`# Web技術 体験会`）。体験会名は企画 Issue「基本情報」表の「体験会名」欄の値で、`taikenkai_slides.py wrap` が定型スライドと同じ名前で入れる（書く時点では `〇〇` のままでよい）。
- `sub` にはその回のテーマ（Issue のタイトル案）を短く。1行に収まる長さにする。
- コメントの**1行目**が `企画 Issue：URL` なのは通常の `lead` と同じ。

### tkb（体験会の本編）

ロゴ 68px・見出しの位置と大きさ・左端からの罫線を `tk` にそろえたクラス。見出しは上端、本文は残りの高さの中で縦中央に置かれる。本文 37px（`dense` は 31px）と大きいので、**通常デッキより入る量が少ない**。

```markdown
<!-- _class: tkb grid -->
<!-- _header: 'PART 02 · スキルとは' -->

## 置き場所は2つ。名前にはルールがある

- **個人用**
  - `~/.claude/skills/名前/SKILL.md`
  - 自分のPCの全プロジェクトで使える
- **プロジェクト用**
  - `.claude/skills/名前/SKILL.md`
  - そのフォルダだけ。Git でチームと共有できる
- **名前のルール**
  - フォルダ名がスキル名
  - ファイル名は必ず **`SKILL.md`**（大文字）

<!--
発表者ノート
-->
```

- **本編の各スライドに付ける**。`_class` は front matter の `class` と合成されないので、`<!-- _class: tkb -->`（クラスなし本文の代わり）、`<!-- _class: tkb grid -->` のようにスライドごとに1行で書く。OVERVIEW・CLOSING も含む。**APPENDIX の `src` / `refs split` だけは `tkb` を付けない**（下記のとおり崩れるため。通常デッキと同じ書き方で置く）。
- PART ラベル（`_header`）は通常どおり。見出しの上に置かれる。

項目数の目安（`decks/20261102_skills.md` と試し書きの PNG で確認した上限。超えると下が切れるか、文字が折り返して崩れる）：

| 併用 | 入る量の目安 |
|---|---|
| `tkb`（本文） | 箇条書き 4〜5 個＋引用 1 行まで |
| `tkb center` | 引用 1 行＋箇条書き 3 個 |
| `tkb grid` | 4 枚なら各カードの説明 2 行まで、3 枚なら各 3 行まで（パスなど長い語は折り返すので 1 行と数えない） |
| `tkb flow` | 4 ステップまで。ステップ名は 6〜7 文字以内（5 ステップだと折り返す） |
| `tkb ba` | 表 4 行＋補足 1 個まで |
| `tkb dense` | 太字ラベル＋コードブロックの組を 3 個まで（2 組＋箇条書き 3 個も可） |
| `tkb dense long` | 15 行程度のコード（SKILL.md の全文など）。コードが 19px になる |
| `tkb stat` | 通常どおり（大きな数字＋補足 2〜3 個） |

- **`tkb` と併用できない**：`trend`（下端に押しやられる）、`pair` / `pair wide`（図の配置が崩れる）、`split` / `refs` / `src`（右パネルが消える・文字が小さくならない・本文が下端に寄る）。推移は `tkb flow` / `tkb ba` で、QR・図は本文の下に画像だけの段落（`![w:220](../assets/xxx.png)`）で置く。
- `check_deck.py --taikenkai` が、表紙が `lead tkt` でない・本編に `tkb` が無い（`src` / `refs` / `split` のスライドは除く）・併用できないクラス・上の目安超え、を WARN で出す。

## 選び方の目安

| 企画 Issue 側の手がかり | クラス |
|---|---|
| 表紙 | `lead`（体験会デッキは `lead tkt`） |
| ゴール・今日の流れ（OVERVIEW） | 本文 / `flow` / `grid` |
| 「見せる数字」が1つの値 | `stat` |
| 数値の推移（〇〇 → 〇〇 → 〇〇） | `trend` |
| 手順・時系列・ステップ | `flow` |
| 3〜4つの観点・軸・選択肢 | `grid` |
| 「半年前はこう → 今はこう」 | `ba` |
| パートの核心を一言で | `center` |
| ハンズオンの操作手順 | `dense` |
| QR・スクリーンショットを添える | `pair` / `pair wide` |
| 注記・参考 | `refs split` / `refs` |
| 出典URL一覧 | `src` |

体験会デッキでは、表紙以外の本編スライドすべてに `tkb` を足す（例：`tkb grid`、クラスなし本文は `tkb`）。`trend` / `pair` / `split` / `refs` / `src` は `tkb` と併用できないので、上の「体験会デッキ」節の代わりの形にする（APPENDIX の `src` / `refs split` は `tkb` なしでそのまま使う）。

同じクラスを連続させすぎない（本文 → `ba` → `center` のように変化をつける）一方、企画 Issue の「Marp 実装メモ」にクラスの指定があればそちらを優先する。
