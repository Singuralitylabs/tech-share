# 体験会の企画 Issue 本文の骨組み

`.github/ISSUE_TEMPLATE/presentation-plan.md` を、体験会（`体験会` ラベル）向けに具体化したもの。
見出し・表の列・太字ラベルは**このまま使う**（`tech-share-deck` スキルと `taikenkai_slides.py` が、この形を前提に読む）。
`〈〉` の部分を埋め、パートの数だけ「各パート」のブロックを増減する。

書き方の実例は Issue #18（2026-11-02「Skills の利用」）。迷ったら #18 の本文を `issue_read` で開いて形をそろえる。

---

````markdown
<!--
この Issue は Tech Share の「企画書」です（体験会）。
合意できたら decks/YYYYMMDD_トピック.md にデッキを作り、デッキ側にこの Issue の URL を記載します。
デッキ完成時のコミット / PR に `Closes #（この Issue 番号）` を書いてクローズします。
体験会ラベル付き：デッキに templates/ の定型スライド（表紙直前と末尾）が必須。差し替え欄（体験会名・開催日程・月次活動）だけ転記時に最新化する。
体験会名は「基本情報」表の「体験会名」欄から転記スクリプトが読み取る。
-->

## 基本情報

| 項目 | 内容 |
|---|---|
| 発表日 | 〈YYYY-MM-DD〉 |
| タイトル案 | 〈テーマ ― ひとことで何ができるようになるか〉 |
| 形式 | 〈ハンズオン（スライド解説＋講師デモ＋ワーク）／座学〉／オンライン |
| 想定時間 | 〈60〉分（月曜 20:00〜〈21:00〉） |
| 対象 | 〈例：プログラミング・AI開発に関心のある初心者（20〜50人）〉。毎回新規参加者が多いので、前回までの知識を前提にしない |
| 体験会名 | 〈AI駆動開発 / Web技術 など。シリーズ名だけを書く（「体験会」は付けない）〉 |
| デッキ | `decks/〈YYYYMMDD〉_〈topic〉.md`（作成予定） |

**関連**：〈カリキュラム Issue・同シリーズの過去の企画 Issue。無ければ行ごと消す〉

**解説環境**：〈講師が画面で見せる環境。例：VS Code ＋ 統合ターミナル。選んだ理由を一言〉

## 事前案内・配布物

**事前案内に入れること**
- 〈インストール・起動確認など、開始前に済ませてほしいこと〉
- 〈有料プランなどの前提があれば。未準備の方は見ているだけでOK、と必ず添える〉

**配布物**
- 配布方法：〈当日 Zoom のチャットでファイル共有／リポジトリ など、その回で決めた方法。未定なら「要確認」〉
- 〈参加者に配るファイル：サンプルコード・練習用データ・依頼文テキストなど〉
- 〈うまくいかなかった人の救済用ファイル（完成形など）〉

**講師が用意するもの**
- 〈デモ用のファイル、チャットに貼る文面、期待する出力の控え など〉

## 狙い・通しのメッセージ

> **狙い**：〈参加者に何を持ち帰ってもらうか。1〜2文〉
> **通しのメッセージ**：〈全パートを貫く一本の主張。太字で一文〉
> **整理の軸**：〈似た概念との使い分けなど、全体の地図になる軸。無ければ行ごと消す〉
> **作り方の軸**：〈作る・設定する回なら「基本は AI に依頼する／公式ツール」を主に、手動は補足〉
> **覚えて帰る1つ**：〈ハンズオンで自分の目で見る一つの変化〉

|---|--------|------|------|------|
| 1 | オープニング（ゴール） | 1 | 2分 | 座学 |
| 2 | 〈パート名〉 | 〈n〉 | 〈n〉分 | 座学 |
| 3 | 〈パート名〉 | 〈n〉 | 〈n〉分 | 座学＋講師デモ |
| 4 | ハンズオン：〈やること〉 | 〈n〉 | 〈n〉分 | 手を動かす |
| 5 | 応用・まとめ | 〈n〉 | 〈n〉分 | 座学 |
| – | 定型（冒頭・末尾：アンケート・支援・今後のイベント・シンラボ紹介） | – | 15分 | 案内 |
| | **合計（本編）** | **〈n〉枚＋表紙** | **〈想定時間と同じ〉分** | |

## スライド構成

> 本編は `tkb` を付けて組む（体験会デッキ）。`tkb` は文字が大きいので 1 枚 3〜4 項目まで。
> `tkb` と併用できない `trend` / `pair` / `split` / `refs` は本編では使わない（`src` は参考スライドだけ）。

| # | パート | 時間 | 枚数 | 各スライドの中身 |
|---|--------|------|------|----------------|
| – | 表紙 | – | 1 | `lead tkt`：〈体験会名〉 体験会＋その回のテーマ |
| 1 | オープニング | 2分 | 1 | ①今日のゴール（`tkb center`） |
| 2 | 〈パート名〉 | 〈n〉分 | 〈n〉 | ①〈中身〉（`tkb`） ②〈中身〉（`tkb grid`） |
| 〈n〉 | ハンズオン | 〈n〉分 | 〈n〉 | ①STEP 1-2（`tkb dense`） ②STEP 3（`tkb dense`） ③できあがりの例（`tkb dense long`） ④STEP 4（`tkb dense`） ⑤止まっていたら（`tkb grid`） |
| 〈n〉 | 応用・まとめ | 〈n〉分 | 〈n〉 | ①〈応用〉（`tkb`） ②まとめ（`tkb center`） |
| – | 参考 | – | 1 | 公式ドキュメントなど（`src`） |
| | **合計** | | **〈n〉枚（表紙込み）** | |

### 配分の考え方
- 〈座学は 1 スライド＝約 1 分。浮いた時間をハンズオンに回す、など〉

## Marp 実装メモ

- **使うレイアウトクラス**：`lead tkt` / `tkb` / `tkb center` / `tkb grid` / `tkb flow` / `tkb ba` / `tkb dense` / `src`
- **ハンズオン**：そのまま打つコマンド・依頼文は `pre`、キー操作は引用＋インラインコード
- **図版が要るスライド**：〈スクリーンショット・QR など。無ければ「なし」〉
- **注意点**：PNG 書き出しではみ出し確認、日本語の太字（`」**` の直後に文字）

## 削ってよい / 注意する要素

- **時間が押したら**：〈削る順番。ハンズオンの本体は削らない〉
- **紹介しないもの**：〈初心者には情報過多な詳細機能など〉
- **要確認**：〈リハーサルで実機確認すること、バージョン依存の挙動。無ければ「なし」〉
````
